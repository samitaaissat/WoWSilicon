# WoWSilicon 3.0.0 — Metal-native Direct3D 9, no CrossOver required

WoWSilicon ships its own Wine, its own Direct3D 9 → Metal renderer, and its own
x87 JIT. Download one app, select your game folder, apply the game patch, play.

## Metal-native rendering: mtld3d is the default

The **Renderer** picker in Options chooses how the game's Direct3D 9 reaches
your GPU:

- **mtld3d (default, recommended)** — [athei/mtld3d](https://github.com/athei/mtld3d),
  a Direct3D 9 implementation written directly against Metal. No Vulkan hop, no
  MoltenVK. Installed the native-override way: a `d3d9.dll` beside the game
  plus the mtld3d builtin pair inside the bundled Wine.
- **d9mt (experimental)** — the other D3D9 → Metal translation layer.
- **d9vk (legacy)** — DXVK's D3D9 over Vulkan/MoltenVK, kept as a fallback.

Switching renderers re-stages the game patch automatically.

**mtld3d notes:** MSAA is not supported (set Multisampling to *Off*; mtld3d
reports the missing capability honestly, so the game falls back cleanly rather
than rendering black). A fullscreen game gets a borderless window covering the
monitor and the display mode is never changed — pick the render resolution with
`render.scale` in the `mtld3d.conf` staged next to your game instead of in the
game's video options. The cursor-size option writes `cursor.scale` there for you.

## x87sidecar replaces the injected rosettax87

The x87 floating-point JIT that makes these clients playable under Rosetta now
runs **out of process** as [athei/x87sidecar](https://github.com/athei/x87sidecar),
attached cooperatively: the game hands over its task port voluntarily at
startup, and the bundled Wine carries the matching handshake patch.

- **No more debugger-authorization prompt** on first launch — cooperative attach
  needs no entitlement.
- It removes the injected-dylib crash class, where a signal arriving while the
  CPU was inside the JIT's own code aborted the process with
  `rosetta error: no code fragment associated with the given arm pc`.

## Bundled Wine runtime

- A pre-patched Wine built from `WineAndAqua/wine` (`wine-11.15-macos`) — no
  CrossOver purchase, install, or patching step.
- macOS **Game Mode** support: the game process is recognized by macOS and gets
  Game Mode's performance and latency priorities.
- The runtime and the renderer payloads update themselves in the background,
  independently of app releases, and every download is checksum-verified. A
  downloaded runtime that is missing anything this app needs is now rejected in
  favor of the one inside the app, instead of being used and failing at launch.
- **MSync** toggle (experimental) for faster Wine synchronization.
- Crashes are reportable: the bundled `winedbg` prints the faulting thread,
  backtrace and registers, and every session is logged under
  `WoWSilicon Data/Logs/`.

## Portable by design

- Everything WoWSilicon needs lives in a `WoWSilicon Data` folder right next to
  the app: your settings and a **dedicated, private Wine environment**. Copy the
  app and that folder together and your whole setup moves — another folder, an
  external drive, a new Mac.
- WoWSilicon never uses the shared `~/.wine` prefix, so it cannot fight with
  CrossOver, other launchers, or system Wine — the number-one cause of "my
  settings randomly reset."
- The first launch sets up the Wine environment explicitly, with progress shown
  (it can take a few minutes — the app tells you instead of looking frozen).
- If the app runs from a read-only place (like the DMG), it temporarily keeps
  data in `~/Library/Application Support/WoWSilicon` and adopts the portable
  folder automatically once you move it somewhere writable. Troubleshooting
  shows which location is active.
- Force Quit is scoped to WoWSilicon's own Wine — it never kills other Wine apps
  on your Mac, and it asks the Wine server to save your registry before stopping.

## Also included

- Addon manager (Git URL installs, bulk import/export), mod manager for
  DLL-style mods, realmlist editor, graphics options, Option-as-Alt, Retina
  mode, vanilla-tweaks.
- Rollback safety: settings written by newer versions can no longer reset your
  game list.
- "Restore CrossOver modifications" in Troubleshooting reverts changes made by
  the 2.x line; WoWSilicon itself never touches a CrossOver install.

As always, drag it into your Applications directory and run:

```sh
xattr -cr /Applications/WoWSilicon.app
```

Supported versions: macOS 15, macOS 26, macOS 27 (Apple Silicon)
